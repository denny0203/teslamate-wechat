# 从零部署 TeslaMate 微信小程序

适用版本：本仓库 v1.0 开源副本。整理日期：2026-10-04。

本文可独立阅读。目标是用自己的阿里云 ECS、阿里云 RDS Supabase 和微信小程序账号，部署一套个人车辆查询服务。命令中的 `YOUR_ECS_HOST`、`YOUR_ACCOUNT`、`YOUR_REPOSITORY` 都需要替换，密钥只在交互提示或私有文件中填写。

这是部署步骤与验收标准；当前开源副本只完成本地验证，尚未按本文在全新云环境走完全流程。控制台菜单、商品规格与审核要求可能调整，以页面实际提示为准。

## 1. 准备账号与环境

准备阿里云账号、Tesla 车主账号、微信小程序账号，以及能够供小程序使用的 HTTPS API 域名。这里主要使用[微信公众平台](https://mp.weixin.qq.com/)的小程序后台；本项目没有微信登录、UnionID 或第三方平台代发布需求，无需为这些功能额外绑定微信开放平台。

建议新建 Ubuntu 24.04 LTS ECS，个人使用可从2核、2GB内存、40GB磁盘起步；历史轨迹持续增长，磁盘和备份空间需按实际增加。该规格为建议，尚未进行负载容量测试。成本包括 ECS、磁盘、带宽、RDS、域名以及可选地图服务；按购买页报价确认，不假定免费试用长期有效。

ECS 与 RDS 可选同一地域／VPC。本文采用 ECS HTTPS 请求 Supabase Data API，不需要开放 PostgreSQL 公网连接。

## 2. ECS 网络与 Docker

在阿里云 ECS 控制台创建实例，使用 Workbench 或已有 SSH 连接维护。SSH 的22端口仅向自己的管理网络开放；不要为数据库、MQTT、TeslaMate、Grafana开放公网端口。本文 Compose 将 TeslaMate 4000和Grafana 3000绑定到回环地址，数据库与MQTT不发布主机端口。

按[阿里云 Docker 安装文档](https://help.aliyun.com/zh/ecs/user-guide/install-and-use-docker)中对应操作系统的步骤安装 Docker Engine 与 Compose 插件；也可参考[Docker Ubuntu 官方文档](https://docs.docker.com/engine/install/ubuntu/)。已有 Docker 环境先检查，不照抄文档的卸载步骤。

验证：

```bash
docker version
docker compose version
python3 --version
systemctl is-active docker
```

后续服务器安装命令在 root 维护终端执行；本机命令会明确标注。不要将服务器密钥复制到聊天或命令参数。

将这个开源目录上传到 ECS 的工作目录，例如 `/root/teslamate-wechat`；GitHub 发布后也可以克隆仓库。上传的是开源子目录，不是个人项目的整个工作区。

## 3. 安装 TeslaMate

在 ECS 的开源仓库根目录执行：

```bash
bash ops/bootstrap.sh
```

脚本只用于首次安装：创建 `/opt/teslamate`，本地随机生成 `.env`，复制 Compose，拉取镜像并启动服务。发现已有 `.env` 或 Compose 时会停止，不覆盖现有数据。脚本不会修改安全组、添加 SSH 密钥或创建 swap。

本仓库沿用个人版 TeslaMate/Grafana 4.3.0，并指定 PostgreSQL 18 与 Mosquitto 2；后两者是可更新标签，严格复现时应记录拉取到的镜像 digest。不要对已有数据库直接更改 PostgreSQL 大版本。

```bash
cd /opt/teslamate
docker compose ps
docker compose logs --tail 50 teslamate
```

如果镜像拉取失败，先检查出网、DNS 和镜像源。可通过自己的阿里云 ACR 镜像仓库保存经核实的上游镜像后修改 Compose；不要关闭 TLS 校验或使用不明来源镜像。上游登录／授权方法以[TeslaMate 官方说明](https://docs.teslamate.org/docs/installation/docker/)及其[Token 说明](https://docs.teslamate.org/docs/installation/tokens/)为准。

本机使用自己的 SSH 配置建立端口转发：

```bash
ssh -N -L 14000:127.0.0.1:4000 -L 13000:127.0.0.1:3000 YOUR_SSH_HOST_ALIAS
```

随后打开 `http://127.0.0.1:14000` 和 `http://127.0.0.1:13000`。Compose 中 `CHECK_ORIGIN` 按14000设置；如果使用其他入口，需同步配置合法 origin。Grafana 初始管理员密码来自服务器私有 `.env`，通过自己的安全维护终端查看该值，不发送到聊天、公开日志或截图。

在 TeslaMate 界面按上游流程完成车主授权，等候采集到自己的车辆、位置、行程和充电数据。新安装没有历史轨迹；本项目不会补造过去的行程。若需要公网后台入口，另行按上游安全部署指南配置 HTTPS、认证或 VPN；本教程默认使用 SSH 隧道。

## 4. 创建阿里云 RDS Supabase

参考[阿里云 RDS Supabase 官方文档](https://help.aliyun.com/zh/rds/apsaradb-rds-for-postgresql/supabase/)：

1. RDS 控制台 → AI能力中心 → Agent开发。
2. 选择地域，进入 RDS AI Application Platform（原 RDS Supabase）页签，创建项目。
3. 完成服务关联角色授权；按需选择 VPC、交换机、RDS规格与存储，勾选 supabase 模块。
4. 设置 Dashboard 与数据库密码，确认费用后创建。
5. 进入项目详情，根据网络信息中的连接地址打开 Supabase Dashboard。

不要删除平台自动创建的数据库或账号。本应用只新增 `public.app_*` 表。

### API 网络访问

Dashboard 管理访问、应用 HTTPS API 访问与 PostgreSQL 数据库连接是不同需求。先为管理电脑与 ECS 的必要访问配置白名单；手机4G／5G的出口IP会变化，不能只允许家中网络。

若托管版本的 Web 应用白名单同时限制手机 API，请在理解控制台实际作用范围后配置 Web 公网访问，并依靠 Auth＋RLS限制业务数据；不要因此将数据库连接白名单或 ECS 数据库端口放开。如 Web 与管理入口共用白名单，开放前需核实管理入口的独立认证与平台限制。以当前控制台行为为准；本文未在新项目复核白名单菜单。

### 获取 URL 与 key

在 Dashboard 的项目设置／API相关页面获取 HTTPS Project URL、legacy `anon` key 和 legacy `service_role` key。URL 是 API origin，不是带 `/project/default` 的 Dashboard 页面地址。

| 配置 | 放置位置 |
|---|---|
| Project URL | 服务器和小程序各自配置 |
| legacy anon key | 小程序配置，只用于低权限客户端接入 |
| legacy service_role key | 服务器 `/opt/teslamate-app/supabase.json`，禁止进入小程序 |
| Dashboard密码／数据库密码 | 自己的密码管理器；本同步服务不需要填数据库连接密码 |

当前代码使用 legacy JWT key 的 Bearer 请求方式，未适配新的 `sb_publishable_` / `sb_secret_` 格式。如控制台没有 legacy keys，先确认提供方的兼容能力，再适配代码；不要用新的 key 强行代替。密钥能力与 RLS 边界参见[Supabase 官方说明](https://supabase.com/docs/guides/getting-started/api-keys)。

### 建表与权限

在 Supabase SQL Editor 中按顺序执行仓库文件的完整内容：

1. `backend/001_app_schema.sql`
2. `backend/002_drive_details.sql`
3. `backend/003_vehicle_history.sql`

三个迁移可重复执行。它们建立4张应用表，启用 RLS，仅向 authenticated 授予 SELECT，并限制 `auth.uid() = owner_id`；服务端 service_role 负责写入。

### 创建登录用户

在 Authentication → Users 创建个人登录用户，设置自己的邮箱和密码，并按平台功能完成邮箱确认，使密码登录可用。关闭公开注册，确保邮箱密码登录提供方启用。记下该用户的 UUID，作为 `owner_id`；不能填写邮箱或微信 OpenID。

默认将源库所有车辆归于这个用户。同一家庭成员共用此登录则看到相同数据；另建账号并不会自动获得记录，不能靠修改客户端配置给另一个账号授权。

## 5. 安装同步服务

回到 ECS，进入开源仓库根目录：

```bash
install -d -m 700 /opt/teslamate-app
python3 tools/configure.py backend
bash ops/install_sync.sh
```

配置工具交互询问 URL、Auth用户UUID、legacy service_role key；密钥输入隐藏，文件权限600，不覆盖已有配置。首次安装脚本先检查4张表可访问，再安装脚本和 systemd unit，运行首轮同步，成功后启用timer。高德补地址timer不会自动启用。

```bash
systemctl status tesla-app-sync.timer
systemctl show tesla-app-sync.service -p Result
journalctl -u tesla-app-sync.service --since today
```

正常情况下 service 为 oneshot，结束后 inactive 是预期；应看 `Result=success`、timer active 和最近成功时间。timer 在上一轮结束后约5分钟再运行，不保证端到端5分钟。

后端三步依次同步行程摘要、轨迹详情、车辆快照。详情每轮最多发布5个变更快照；首次历史回填可能需要多轮。私有状态文件：

- `last-sync.json`：摘要同步结果。
- `last-details-sync.json`：本轮详情结果与 `history_pending`。
- `last-vehicles-sync.json`：车辆快照结果。

需要追加一轮时：

```bash
systemctl start tesla-app-sync.service
```

正常完成回填应看到 `history_pending=0`，近期变更完成后 `remaining=0`。这些数值不证明坐标与手机地图显示已验收。

安装首轮失败时timer不会启用：修复配置／迁移／网络后手动启动service，确认成功再执行 `systemctl enable --now tesla-app-sync.timer`。不要重复调用首次安装脚本覆盖文件。

## 6. 可选：高德端点地址解析

先确认 TeslaMate 本身的地址解析是否已满足需求；不启用本步骤也能运行小程序，缺失地址显示相应空态。

在[高德开放平台](https://lbs.amap.com/)创建应用，申请 Web服务 key，并按其当前控制台要求设置服务器出口IP等限制。坐标转换和逆地理编码接口会接收行程端点坐标，不发送整段轨迹；费用与配额以平台实际规则为准。

此模块会补写源库 `addresses` 表及 `drives` 缺失地址关联，不修改 GPS，不覆盖已有地址。因此开启前先备份 TeslaMate，并确认接受源库补写。

在 ECS 开源仓库根目录执行：

```bash
python3 tools/configure.py amap
systemctl start tesla-app-geocode.service
systemctl show tesla-app-geocode.service -p Result
```

首轮成功且检查符合预期后，再启用周期执行：

```bash
systemctl enable --now tesla-app-geocode.timer
```

停止未来补写：

```bash
systemctl disable --now tesla-app-geocode.timer
```

该命令不终止已经运行的 oneshot，也不撤销已写地址。维护前查看service状态并等待本轮结束。不要通过删除地址表回退；确需恢复数据时遵循备份恢复流程。

## 7. 微信公众平台与开发者工具

### 创建小程序与开发者

登录[微信公众平台](https://mp.weixin.qq.com/)，注册或进入自己的小程序账号。根据用途选择主体、类目，完成平台要求的身份／备案／隐私及其他前置项；是否可以审核发布以后台实际提示为准，开源代码不保证审核通过。

获取小程序 AppID，将开发人员加入项目成员。下载[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，由管理员或已加入的开发者扫码登录。本文不需要获取或配置 AppSecret。

### 配置客户端

在本机开源仓库根目录执行：

```bash
python3 tools/configure.py client
```

填写同一 Supabase 项目的 HTTPS URL 和 legacy anon key。工具会拒绝 service_role key。生成的 `miniprogram/config.js` 被 Git 忽略；客户端 key 虽可公开，仍推荐不提交个人项目的连接配置。

开发者工具导入 `miniprogram/`，填写自己的 AppID；检查 `project.config.json` 的 `touristappid` 已替换。只有该目录是微信代码包，不上传后端、教程或服务器配置。

### 配置服务器域名

在小程序后台的开发管理／开发设置中配置 HTTPS request 合法域名，填写小程序实际请求的 Supabase API origin。不是 ECS IP，也不是 TeslaMate 的4000端口；保持域名校验开启。

若平台不接受服务提供方域名，需要自己的合规域名与有效 TLS 证书，再通过受控 HTTPS 反向代理转发 `/auth/v1/` 与 `/rest/v1/` 到 Supabase，并将客户端URL改为该origin。该分支未提供自动代理脚本，须另行配置和验证；证书、域名备案及其他要求按微信当前规则办理。不能把“开发工具忽略域名校验”当作正式解决方案。

默认地图未使用个性化 subkey。高德 Web服务 key 不放入 `map.config.js`；地图个性化能力若需开通，按微信与腾讯地图的实际权限配置。

参考[微信网络能力文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。整理时该官网正文无法由检索工具读取，后台菜单和准入细节需在实际操作中复核。

### 预览、上传、审核与发布

1. 开发者工具编译，确认没有依赖缺失或配置错误。
2. 预览扫码，用 Supabase 邮箱密码登录。
3. 在 Wi-Fi 和手机移动网络下验收，退出后核实私人页面已清除。
4. 上传代码，填写版本和版本描述。
5. 公众平台 → 版本管理：检查开发版本，按后台要求提供类目、隐私说明、必要的审核账号与材料，提交审核。
6. 审核通过后发布。开发预览、上传成功和正式发布是三个不同状态。

只通过微信审核要求的受控渠道提供专用审核账号；不把真实车主密码、轨迹或后台密钥写入开源仓库。审核所需演示数据应使用独立配置与虚构记录。

## 8. 权限与端到端验收

必须在自己新建的项目复核，而不能用本仓库的单元测试代替：

- 本人登录后能读取4张应用表中归属本人的记录。
- 第二个无归属测试用户登录后，4张表均返回空数组。
- 不登录，直接通过 anon key 请求4张表，均无读取权限。
- authenticated 用户对4张表的 INSERT／UPDATE／DELETE权限均为false。
- service_role key 仅出现在服务器私有配置，不出现在小程序构建包。
- 源库与目的库核对短途、长途、缺失地址、无轨迹等记录的时间、里程、估算能耗及断段。
- iOS／Android验证地图、返回与切换、按日边界、下拉刷新、弱网错误及长轨迹；4G／5G成功不能只由Wi-Fi结果推断。

可在 SQL Editor 查看表权限和 RLS：

```sql
SELECT c.relname, c.relrowsecurity,
 has_table_privilege('anon', c.oid, 'SELECT') AS anon_read,
 has_table_privilege('authenticated', c.oid, 'SELECT') AS user_read,
 has_table_privilege('authenticated', c.oid, 'INSERT') AS user_insert,
 has_table_privilege('authenticated', c.oid, 'UPDATE') AS user_update,
 has_table_privilege('authenticated', c.oid, 'DELETE') AS user_delete
FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
WHERE n.nspname='public' AND c.relname IN
 ('app_drives','app_drive_details','app_vehicles','app_sync_status');
```

此SQL只检查权限，不代替真实两个用户的 API 隔离测试。SQL Editor 的管理员查询不能证明客户端有权限或没有权限。

## 9. 备份、升级与回退

TeslaMate 备份在 ECS root 终端执行：

```bash
cd /opt/teslamate
umask 077
docker compose exec -T database pg_dump -U teslamate teslamate > "backups/teslamate-$(date -u +%Y%m%dT%H%M%SZ).bck"
```

同时用自己的加密备份方式保存 `.env` 中的加密密钥及必要配置，将备份保留在另一安全位置，验证文件非空并演练恢复。[上游备份说明](https://docs.teslamate.org/docs/maintenance/backup/)

应用升级前停止sync timer，等待service结束，备份 `/opt/teslamate-app` 与4个systemd unit到服务器私有目录，再替换新脚本、执行增量迁移、daemon-reload、手动运行service，成功后恢复timer。不要用首次安装脚本做升级。回退时恢复对应版本脚本与unit，不自动删除应用表或源库数据。

高德模块也需停止timer并等候本轮结束。停止同步只是暂停目的库更新，不删除记录。私有配置备份不应进入 GitHub。

## 10. 常见问题

| 现象 | 排查 |
|---|---|
| 登录400／401 | 邮箱密码、邮箱确认、Auth提供方、密钥格式、是否误用Dashboard密码 |
| service报HTTP401／403 | URL对应项目、legacy service_role key、API网络限制 |
| service报404 | 三个迁移是否执行、REST schema是否刷新 |
| ForeignKeyViolation | `owner_id` 是否来自同一项目的Authentication用户 |
| 行程有摘要但详情等待中 | 首次回填队列，每轮最多5个变更；检查history_pending |
| Wi-Fi可用而4G不可用 | Web应用白名单、API公网访问、合法域名和证书 |
| 轨迹缺段／地址缺失 | 查看源库是否有点；不连接缺段，不猜测旧位置 |
| 安装脚本拒绝已有文件 | 为保护现有部署；按升级／回退步骤操作 |
| 本地测试通过但小程序报错 | 单元测试不代替开发者工具构建、域名检查和真机验收 |

相关外部文档以上链接为准。控制台及审核细节变化时更新本文，保留已验证日期。
